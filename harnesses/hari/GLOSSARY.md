# Hari glossary

## Hari

The named cross-project coordination agent who uses the Hari harness through
native Pi. Hari is a name, not an acronym. Hari keeps compact cross-project
coordination knowledge, retrieves detail when needed, and exercises judgment within
agreed authority. He does not become a project-manager tier or routinely re-review
technical implementation.

## Hari harness

The local software under `harnesses/hari` in pi-squared. It hosts Hari, defines
his tools and role boundaries, and integrates native Pi and workspace capabilities.
It is not Hari himself or his private memory.

## Prime Radiant

Hari's durable home at `~/Projects/primeradiant`. His own durable agent data
includes coordinator conversations, structured coordination knowledge, and local
checkpoints. Prime Radiant is separate from the
harness source and is not a selectable instance or a copy of every project source,
credential, external record, or manager session.

## Project

A grouping of one or more issues, decisions, dependencies, and managers. A single
issue may be a project.

## Issue and sub-issue

A unit of work with an intended outcome. Use *sub-issue* when the parent-child
relationship matters. An issue may be local or GitHub-backed.

## Inbox item

A local note that has not become assigned work. It does not require a project,
GitHub issue, acceptance criteria, or manager.

## Manager

The agent responsible for one complete issue or sub-issue. It owns technical
discovery, execution choices, evidence, and its completion recommendation within
its assignment.

## Manager assignment

The recorded outcome, acceptance criteria, constraints, authority, and prepared
checkout for a manager. It is not a prewritten implementation plan.

## Acceptance criterion

A verifiable condition of the agreed outcome. Evidence, an explicit deferral, or
a blocker describes its disposition. A deferral is not a pass.

## Task and subagent

A task is a bounded execution slice within a manager's assignment. A subagent is
optional bounded help chosen by that manager. Delegation does not transfer issue
ownership, full acceptance responsibility, or authority.

## Prepared checkout

The explicit repository path and local branch agreed for a manager's source work.
It is distinct from the manager identity and exact native Pi session binding.

## Manager report

The manager-owned concise record of its result, evidence references, coordination
impact, blockers, and exceptions. It is input to coordination, not a replacement
for source evidence.

## Authority and advisory boundary

The agreed scope, actions, constraints, and escalation conditions for work. The
harness checks help cooperative agents follow that boundary. They are not a sandbox
or proof that another execution route is impossible.

## Company guidance

Company-specific knowledge, skills, conventions, and glossary material that belongs
in the Prime Radiant. It is separate from generic Hari harness guidance under
`harnesses/hari` and is not automatically loaded, written, or checkpointed by the
harness.
